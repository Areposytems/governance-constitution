# Changelog — Domain Profiles v0.1

## Legal Domain Profile v0.1

* Revised the legal profile from common-law leaning terminology into a jurisdiction-neutral legal translation profile.
* Added a jurisdiction-neutral interpretation section.
* Added `jurisdictional_adaptation_note.md` for local legal-system translation.
* Expanded legal-domain translation terms to include adjudicative, administrative, regulatory, institutional, and rights-affecting contexts.
* Replaced narrower terms such as solicitor and affidavit with broader functional equivalents.
* Added due process, natural justice, attorney-client privilege, professional secrecy, administrative review, and equivalent local-law concepts.
* Added expiry, review, withdrawal, and renewal concepts to operational governance questions.
* Updated the legal adoption checklist, risk-benefit matrix, governance mapping, court/tribunal adoption guide, and legal LBA example for jurisdiction-neutral adoption.

## Agentic Software Systems Domain Profile v0.1

* Added an environment-neutral Agentic Software Systems Domain Profile.
* Added `software_environment_adaptation_note.md` for translation across local software platforms, workflows, roles, permissions, and deployment environments.
* Added a GitHub-style agentic workflow adoption guide.
* Added an agentic software governance mapping.
* Added an agentic software risk-benefit matrix.
* Added an agentic software adoption checklist.
* Added an illustrative agentic pull request Legitimacy Binding Artifact example.
* Defined risk categories for assistive, repository-modifying, workflow or security-sensitive, operational, and prohibited or exceptional uses.
* Clarified that the profile does not create software safety, cybersecurity, legal, regulatory, compliance, audit, certification, or production-readiness approval.
* Preserved explicit authorization, scope, expiry, evidence references, non-delegation, proof-carrying change, reviewability, and accountable responsibility.
