## Purpose

This package translates the Governance Constitution into agentic software systems language for AI coding agents, repository workflows, CI/CD systems, tool-using models, software automation environments, developer platforms, and institutional software operations.

It is intended to support early review, discussion, adoption planning, and implementation design for agentic software governance.

## Relationship to the Domain Profile Contract

The main profile provides the environment-neutral domain translation.

The adaptation note supports local terminology and workflow translation. The governance mapping, risk-benefit matrix, and adoption checklist address operational questions, roles, risks, boundaries, and adoption considerations.

The related adoption guide is setting-specific and non-normative. The LBA example is illustrative only and is not a complete implementation, authorization, approval, or compliance template.

Together, these materials form the Agentic Software Systems Domain Profile package while preserving the distinction between:

* constitutional requirements;
* domain translation;
* adoption guidance;
* illustrative examples;
* external technical, legal, security, regulatory, and institutional duties.

## Boundary

This package does not create software safety, cybersecurity, legal, regulatory, compliance, audit, certification, or production-readiness approval by itself.

Local adoption requires review by accountable technical, security, legal, regulatory, professional, and institutional authorities where applicable.

## Core claim

AI agents may assist software work, but they must not obscure authorization, silently expand scope, bypass review, alter consequential systems without proof-carrying records, replace accountable human judgment, or allow responsibility to disappear into automation.
